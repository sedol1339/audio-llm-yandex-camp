# Постановка задачи

**Учёт темы и истории разговора для повышения качества распознавания речи.**

Ошибки распознавания речи обычно возникают, когда модель выбирает неверный вариант среди нескольких похоже звучащих слов. Здесь может помочь дополнительный контекст:
- Указание тематики разговора (например, «машинное обучение»)
- База текстов или слов по указанной тематике
- Доступная история разговора (как правило без эталонной разметки).

Эти данные могут использоваться:
- В text-to-speech модели
- В декодировании с помощью N-грамной языковой модели
- В коррекции транскрипции с помощью отдельной языковой модели

Потенциальные сложности:
- Для оценки качества нужно собрать реалистичный и разнообразный датасет с достаточным количеством ошибок распознавания, которые можно исправить учетом контекста (не все ошибки таковы), и наличием самого контекста. Если в датасете суммарно будет мало ошибок или мало аудио, то может не хватить стат. значимости при сравнении методов. Длинные доменно-специфичные аудио с ручной разметкой почти не представлены на русском языке. Например, для тестирования [Писца](https://aclanthology.org/2025.naacl-industry.74/) мы собирали датасет [long audio youtube lectures](https://huggingface.co/datasets/dangrebenkin/long_audio_youtube_lectures) из 7 длинных записей лекций, размеченных вручную. Другие подобные датасеты, такие как [bobr video](https://huggingface.co/datasets/ZeroAgency/shkolkovo-bobr.video-webinars-audio), содержат автоматическую разметку. Сплиты ru000 и ru001 датасета [YODAS](https://huggingface.co/datasets/espnet/yodas2) содержат данные с Youtube с разметкой, загруженной пользователем, но такая разметка тоже чаще всего автоматическая.
- Базы текстов как правило не содержат просторечных форм терминов, а история разговора может содержать, но на инференсе не будет содержать эталонной разметки. Указание же тематики менее актуально для длинных фрагментов аудио, где тематика и так становится понятна из текста, и дополнительное явное ее указание может не дать новой информации.
- Большой контекст не обязательно улучшит качество, потому что вызовет сдвиг данных: входные тексты будут длиннее, чем при обучении, что может нарушить работу модели. Если же дообучать на длинных контекстах, тогда необходим еще и обучающий датасет, и в случае его чрезмерного сходства с тестовым мы получим завышенную оценку качества.
- Модели распознавания речи часто выдают неверные, но уверенные предсказания – слова, семантически правдоподобные, но не соответствующие произнесенным. Это может быть вызвано тем, что text-to-speech модель выполняет собственное языковое моделирование, и из-за несовершенства внутренней языковой модели эта стадия работает плохо. Таким образом, распределения вероятностей оказываются «испорчены» слабой внутренней языковой моделью и больше не отражают фонетическое правдоподобие, поэтому внешняя, дополнительная модель (N-грамная, GPT, BERT) не всегда может исправить ситуацию.

# Организация работы

Яндекс кемп предполагает самоорганизацию команды, то есть участники команды сами распределяют между собой роли. Задачи тоже можно ставить самим. Роль ментора в основном в том, чтобы обсуждать с ним планы и результаты, спрашивать что-то. Организаторы просят, чтобы команда делала фоллоу-апы после встреч с менторами и фиксировали их (предлагаю описывать ход работ в этом же репозитории в папке docs). Ментор предоставляет сервера, но можно и арендовать сервера самим на грант, выданный команде.

Будет удобно, если одна половина команды займется моделями, а другая датасетами и системой оценки, в другую половину команды перейти можно.

# План работы по проекту

Изучать модели и писать код для инференса можно сразу, с датасетами сложнее. Уже есть набор готовых датасетов `src/datasets_list.py`, но там в основном короткие аудио и без дополнительного контекста. Чтобы собирать данные, желательно сначала изучить типологию ошибок, дпускаемых моделями на текущих датасетах, и понять какой контекст мог бы помочь исправить эти ошибки. Далее можно взять из интернета соответствующий контекст. При этом надо понимать сценарий работы системы в проде: пользователь сам дает контекст, или он ищется автоматически во время выполнения запроса на расшифровку адуио? Если автоматически, то нужно подготовить автоматический метод для оценки.

Как вариант, на русском языке доступен датасет YODAS (https://huggingface.co/datasets/espnet/yodas2) с большим объмемом аудио с Youtube с открытой лицензией. Мы можем сделать поиск в YODAS по тематикам и найти набор длинных аудио. Для каждого аудио получить транскрипцию, например, с помощью GigaAM2. Проанализировать фрагменты транскрипций, чтобы понять частоту возникновения ошибок и их типологию (можно ли исправить их учетом контекста). На основе этого создать датасет, каждый пример которого содержит:
- Длинное аудио
- Ручную транскрипцию для фрагмента с указанием границ фрагмента
- Дополнительный контекст

Технически, предлагаю такие задачи на первое время:

**Данные и система оценки:**
1. Реализовать интерфейс визуальной оценки предсказаний (множественное выравнивание предсказаний методу моделями для визуального сравнения, для примера см. multiple sequence alignment из биологии).
2. Настроить систему хранения предсказаний через hyperyaml. Хранить предсказания моделей важно, если мы захотим визуализировать или пересчитать метрики, не выполняя заново инференс. Hyperyaml удобен тем, что можно удобно хранить датаклассы, например, MatchesList из `src/asr_eval/align/data.py`, потому что они тоже занимают время на расчет. Но можно хранить и в обычных txt или json.
3. Разобраться с хранием данных и другими возможностями yandex datasphere

**Модели**
1. Настроить wrapper с параметрами для Qwen2-Audio
2. Настроить wrapper с параметрами для Gemma-3n
3. Настроить wrapper с параметрами для Voxtral
4. Попробовать контекст в whisper longform. Можно начать с `src/asr_eval/models/whisper_wrapper.py` и найти на HF параметры Whisper, отвечающие за передачу предыдущего контекста, сравнить качество.
5. Поиск других audio-LLM, обзор области
6. Изучить код Whisper Prompt-conditioning Fine-tuning из статьи, найденной Василием https://arxiv.org/abs/2307.10274
7. Изучить Contextualizer ASR with controllable Style из статьи, найденной Василием https://www.arxiv.org/abs/2309.07414
