# Организация виртуальных машин

Для проекта можно создать на команду по одной прерываемой GPU-машине (включается на несколько часов на время работы) и по одной более дешевой не-прерываемой CPU-машине, где участники смогут продолжать работу в любое время.

Пара машин (GPU+CPU) имеют разные локальные диски, но могут иметь общее файловое хранилище, чтобы команде не нужно было копировать наработки между машинами когда GPU-машина выключается.

Можно заранее придумать названия машин, например:
1. Для команды 1: camp-0-gpu, camp-0-cpu имеют общее хранилище camp-0-storage
2. Для команды 2: camp-1-gpu, camp-1-cpu имеют общее хранилище camp-1-storage

Если хотите, чтобы команды имели общее хранилище файлов, можно создать одно хранилище, или даже одну пару машин на две команды.

# Установка квот

Идем в https://console.yandex.cloud/, жмем 9 точек сверху слева, набираем в поиске "quota", жмем Yandex Cloud Quota Manager.

1. Вводим "Количество статических публичных IP-адресов" и жмем повысить до 5.
2. Вводим "Количество A100" и жмем повысить до 2. Здесь возможно потребуется диалог с теходдержкой.
3. Ищем "Общий объём сетевых файловых HDD-хранилищ", повышаем до 2000 гб.
4. Ищем "Общий объём SSD-дисков", повышаем до 400 гб.

# Создание файловых хранилищ

Идем в "Compute Cloud/Файловые хранилища", жмем создать, имя camp-0-storage, зона ru-central1-a (эта зона влияет на доступные GPU), создаем HDD 1000 гб. Аналогично в той же зоне ru-central1-a создаем второе хранилище camp-1-storage.

Проверяем, что в разделе "Файловые хранилища" два хранилища в статусе ready.

# Создание виртуальных машин

Идем в "Compute cloud/Виртуальные машины", "Создать", "расширенная настройка":

1. ОС Ubuntu 24.04
2. Зона доступности ru-central1-a
3. Диск SSD 100 гб (загрузочный)
4. Добавить диск - Файловое хранилище - camp-0-storage
4. Вычислительные ресурсы - своя конфигурация - платформа - есть GPU - A100 - ставим галочку "прерываемая".
5. Указываем свой логин и публичный ssh-ключ (можно создать через `ssh-keygen -t rsa -b 4096` на домашнем ПК)
6. Имя сервера camp-0-gpu

Аналогичным образом создаем остальные машины с привязкой хранилищ.

Для CPU машин можно выбрать 2 CPU, 4 Gb RAM, в этом случае гранта должно хватить по цене на все машины, если GPU будут работать по 26 часов (суммарное время работы команд над проектами по плану), а CPU будут работать круглосуточно.

При создании машин снова могут вылезти ограничения по квотам, в этом же окне их можно поднять.

В "Compute cloud/Виртуальные машины" проверяем, что у нас 4 машины, проверяем информацию во всех колонках. Останавливаем все машины.

# Установка статических IP

Выбираем GPU-машину, заходим на ее страницу, справа сверху три точки, "остановить". Появится окно, где жмем "сделать IP статическим", чтобы он не менялся при каждом перезапуске. Аналогично с остальными машинами.

Альтернативно, идем в "Virtual Private Cloud/IP-адреса" и жмем там сделать все адреса статическими. Там же можно удалить неиспользуемые адреса, если такие возникли. Проверяем, что в списке 4 статических IP-адреса.

Чтобы не запоминать IP, можно добавить их на ПК, с которого будете подключаться, в файл c:\windows\system32\drivers\etc\hosts, например:

```
158.160.33.135 camp-0-gpu
158.160.40.22 camp-1-gpu
51.250.79.255 camp-0-cpu
158.160.44.207 camp-1-cpu
```

(или в C:\Users\yourname\.ssh\config)

# Монтирование файлового хранилища

Включаем все сервера, проверяем, что на любой сервер можно зайти

`ssh yourname@ip -i <путь к приватному ключу без .pub>`

Если без пароля не пускает, значит неправильно настроен или передан ssh-ключ. Если ключ находится по адресу C:\Users\yourname\.ssh\id_rsa, то путь к нему можно не указывать. Если имя сервера находится в hosts, можно указать вместо IP:

`ssh yourname@camp-0-cpu`

На каждом сервере нужно смонтировать файловое хранилище. Чтобы получить имя хранилища, заходим на страницу машины, жмем "Файловые хранилища", жмем на хранилище и копируем идентификатор, например fhm5sg4988dj60hkhp3k. Затем вводим в ssh-сессии на сервере команду с этим id:

```
sudo mkdir /storage
sudo mount -t virtiofs fhm5sg4988dj60hkhp3k /storage
```

Можно создать файл в /storage в одном сервере и проверить, что файл появится на другом сервере.

# Добавление пользователя

Добавить пользователя может любой другой пользователь с правами sudo. Логиниться на сервере считается безопаснее и удобнее через SSH, а не пароль. Для этого:

1. Пользователь, которого нужно добавить, создает у себя на рабочем/домашнем компьютере, с которого будет подключаться, пару ключей. Это можно сделать командой `ssh-keygen -t rsa -b 4096` и принять дефолтный путь к файлу, который будет предложен. Будет сгенерирована пара ключей, например:

```
%USERNAME%/.ssh/ir_rsa
%USERNAME%/.ssh/ir_rsa.pub
```

Публичный ключ нужно отправить любому существующему пользователю сервера с правами sudo. Добавим пользователя с правами sudo:

`useradd -m -d /home/username/ -s /bin/bash -G sudo username`

Добавим ssh-ключ:

```
mkdir /home/username/.ssh
nano /home/username/.ssh/authorized_keys
(далее копируем публичный ключ в файл и сохраняем)
chown -R username:username /home/username/.ssh
chmod 700 /home/username/.ssh
chmod 600 /home/username/.ssh/authorized_keys
```

После этого username с домашнего ПК сможет подключиться:

`ssh username@ip`

Если ключ хранится не по стандартному пути, надо его указать

`ssh username@ip -i <путь к приватному ключу без .pub>`

# Подключение через VS Code

Открываем file - preferences - settings, вводим в поиск remote-ssh. Видим поле, куда указываем путь к конфиг файлу, например:

C:\Users\yourname\vscode_config

В этом файле пишем следующие строки, где указываем ip и путь к приватному ssh ключу, например:

```
Host 87.228.65.127
User oleg
IdentityFile C:\Users\Oleg\.ssh\ir_rsa
```

После этого VS Code не должна запрашивать пароль при подключении по адресу oleg@87.228.65.127.

# Подключение к Github

Если мы будем делать pull и push на github с сервера, то на сервер нужно установить GitHub CLI: `sudo apt install gh`

1. Отправить свое имя пользователя Github и принять приглашение в коллабораторы проекта https://github.com/sedol1339/audio-llm-yandex-camp , чтобы можно было пушить изменения в этот проект.

2. Зайти в https://github.com/settings/tokens/new и создать новый токен с любым именем, ставим галочки в выбираем repo, workflow, read:org. Нажимаем Generate token и копируем сгенерированный токен.
 
3. На сервере вводим команды `git config --global --replace-all credential.helper store`, `gh auth login` и выбираем: github.com - HTTPS - Y - Paste an authentication token - вставляем токен. Система напишет в какой аккаунт вы залогинились. Проверяем:

```
mkdir /storage/$USER
cd /storage/$USER
git clone https://github.com/sedol1339/audio-llm-yandex-camp
```

# Настройка HF кэша

Большие файлы лучше хранить на /storage, чтобы загрузочный SSD-диск не забивался. Туда же удобнее клонировать проект.

Создаем в проекте файл .env и пишем там (этот файл хранит переменные среды для ноутбуков):

```
HF_CACHE=/storage/<your user name>/.cache/huggingface
```

Открываем редактор через `nano ~/.bashrc`, в начало файла добавляем такую же строку. Сохраняем через Ctrl-X, жмем Y, <enter>
